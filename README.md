# Markdown Preview Themes

A VS Code extension that applies a colour theme, fonts and custom CSS to the built-in Markdown
preview. It ships 60 colour themes extracted from CodeMirror 5 stylesheets, including the 49 used
by [programmingfonts.org](https://www.programmingfonts.org), a theme editor panel, a theme browser
page, nine colour overrides, and two custom CSS inputs.

The extension injects a `<style>` element into the rendered preview on every render. A settings
change takes effect on the next render; no reload is required.

## Installation

The extension is installed from a locally packaged `.vsix`.

```sh
cd ~/WORK/TOOLS/vscode-markdown-preview-themes
npm install
npm run package          # typecheck, lint, smoke test, then build dist/ and write markdown-preview-themes-<version>.vsix
code --install-extension markdown-preview-themes-0.1.0.vsix --force
```

`npm run install-local` runs the last two steps. A window reload is required after installation.

For another VS Code profile, add `--profile <name>` to the install command. Settings are stored per
profile.

### Interaction with Markdown Preview Github Styling

`bierner.markdown-preview-github-styles` wraps the preview content in an element with its own
background and text colour. This extension sets that wrapper's background to transparent and its
text colour to inherit, so the selected theme's page colours apply. The GitHub stylesheet still
sets spacing, table, list and scrollbar styles. Disabling that extension removes the remaining
differences.

## Use

1. Open a Markdown file and its preview (`Cmd+Shift+V` or `Cmd+K V`).
2. Run **Markdown Preview Themes: Open Theme Editor** from the command palette, or use the icon in
   the title bar of a Markdown editor. The editor opens beside the preview.
3. Each control writes to user settings immediately. The preview and the editor's sample pane
   update on the same change. **Revert to opening state** restores the settings read when the
   editor opened.

### Commands

| Command | Behaviour |
|---|---|
| Open Theme Editor | Opens the editor panel: theme, fonts, colour overrides, custom CSS, live sample |
| Open Theme Browser | Opens the bundled theme page in a VS Code tab. Clicking the settings box at the bottom writes the shown values to user settings. |
| Open Theme Browser in Web Browser | Opens the same page in the default web browser |
| Select Theme, Select Light Theme, Select Dark Theme | Quick pick over all themes for the corresponding setting |
| Next Theme, Previous Theme | Steps through the theme list for the setting in effect (`theme`, or `lightTheme`/`darkTheme` by current VS Code appearance in `auto` mode) |
| Export Current Theme as CSS | Writes the generated stylesheet to a `.css` file |
| Open Preview as Markdown (Quarto / other) | Sets the active document's language mode to Markdown and opens the preview beside it |

Keybinding example (`keybindings.json`):

```json
{ "key": "ctrl+alt+]", "command": "markdownPreviewThemes.nextTheme" },
{ "key": "ctrl+alt+[", "command": "markdownPreviewThemes.previousTheme" }
```

### Entry points to the theme browser

- The **Open Theme Browser** command.
- The **Browse all themes** link in the description of the `mode`, `theme`, `lightTheme` and
  `darkTheme` settings in the Settings UI.
- The icon in the title bar of a Markdown editor.
- The URI `vscode://fpontejos.markdown-preview-themes/browse` from outside VS Code
  (`open "vscode://fpontejos.markdown-preview-themes/browse"` on macOS). `…/editor` opens the theme
  editor. VS Code asks for confirmation the first time the extension handles a URI.

The Extensions view renders this README with `http`, `https` and `mailto` links only. Links to local
files, `vscode:` URIs and `command:` URIs are not clickable there.

## Theme browser page

`docs/site/index.html` is a single file with no external resources. It is generated by
`npm run site`, and a copy is bundled as `dist/themes.html`.

Contents and controls:

- Sidebar listing all 60 themes with a light/dark tag and eight colour swatches each. Filters by
  name and by light/dark.
- Arrow keys, `j`/`k`, and the ↑ ↓ buttons step through the visible themes.
- Header inputs for body, heading and code font family (free text, with suggestion lists), font
  size, line height and content width.
- Sample document rendered with the same CSS the extension injects, scoped to the page.
- A box at the bottom showing the `settings.json` lines for the current choice. In a web browser a
  click copies them. In the VS Code tab a click writes them to user settings.
- The URL hash records theme and font choices.

## Settings

All settings are under `markdownPreviewThemes.*`.

| Setting | Default | Meaning |
|---|---|---|
| `mode` | `fixed` | `fixed` uses `theme`. `auto` uses `lightTheme` when VS Code has a light colour theme and `darkTheme` when dark. |
| `theme`, `lightTheme`, `darkTheme` | `none` | Theme id. `none` keeps VS Code's own preview colours. |
| `fontFamily`, `headingFontFamily`, `codeFontFamily` | `""` | CSS `font-family` values. Empty inherits `markdown.preview.fontFamily`, the body font, and `editor.fontFamily` respectively. |
| `fontSize`, `codeFontSize` | `0` | Pixels. `0` inherits. |
| `lineHeight` | `0` | Unitless. `0` inherits. |
| `maxWidth` | `0` | Pixels, content centred. `0` is full width. |
| `colors` | `{}` | Hex overrides applied to both light and dark: `background`, `foreground`, `heading`, `link`, `codeBackground`, `codeForeground`, `border`, `blockquote`, `selection` |
| `customCss` | `""` | CSS appended after the theme rules |
| `customCssPath` | `""` | Path to a CSS file appended after the theme rules and before `customCss`. Absolute, `~`-prefixed, or relative to the first workspace folder. The file is watched; a change refreshes the preview. |

Example `settings.json`:

```json
"markdownPreviewThemes.mode": "auto",
"markdownPreviewThemes.lightTheme": "solarized-light",
"markdownPreviewThemes.darkTheme": "catppuccin-macchiato",
"markdownPreviewThemes.fontFamily": "Charter, Georgia, serif",
"markdownPreviewThemes.codeFontFamily": "\"JetBrains Mono\", monospace",
"markdownPreviewThemes.fontSize": 16,
"markdownPreviewThemes.lineHeight": 1.6,
"markdownPreviewThemes.maxWidth": 820,
"markdownPreviewThemes.colors": { "link": "#d33682" },
"markdownPreviewThemes.customCss": "body.vscode-body h1 { letter-spacing: -0.02em; }"
```

### Custom CSS

- The preview root is `body.vscode-body`. VS Code adds `vscode-light`, `vscode-dark`,
  `vscode-high-contrast` or `vscode-high-contrast-light` to the same element.
- Code blocks use highlight.js classes (`.hljs-keyword`, `.hljs-string`, and so on).
- Generated rules are scoped to `body.vscode-body`. A custom rule with the same selector prefix has
  equal specificity and takes precedence by source order. A rule that does not apply needs higher
  specificity or `!important`.
- **Export Current Theme as CSS** writes the stylesheet the extension injects for the current
  settings.

### Derivation from CodeMirror themes

`scripts/extract-themes.mjs` parses each vendored stylesheet and records the editor background and
foreground, gutter background, selection colour, and the colour of each `.cm-*` token class.
`src/theme-css.ts` derives the preview colours:

| Preview element | Source |
|---|---|
| Page background, text | editor background, foreground |
| Headings | `cm-header`, else `cm-def`, else text |
| Links | `cm-link`, else `cm-atom`, else `cm-keyword` |
| Code background | gutter background when it differs from the page, else page mixed 5–6 % toward text |
| Borders, rules, table lines | page mixed 25 % toward text |
| Blockquote | `cm-quote`, else `cm-comment` |
| Selection | editor selection colour |
| highlight.js tokens | `comment`, `keyword`, `string`, `number`/`atom`, `def`, `attribute`, `tag`, `builtin`/`type`, `variable`, `meta`, `link` |

CodeMirror themes without a declared background (`eclipse`, `elegant`, `idea`, `juejin`, `neat`,
`ssms`, `ttcn`, `vibrant`, `xq-light`) are excluded. They inherit CodeMirror's default white and
provide no base colours.

## Quarto and other document types

The built-in preview opens for documents in the `markdown` language mode. The Quarto extension
registers `.qmd` as the `quarto` language, so the preview command is not offered for those files.

- **Open Preview as Markdown** sets the active document's language mode to Markdown for the session
  and opens the preview beside it. Quarto editor features are inactive while the mode is switched.
  The language picker in the status bar restores it.
- `"files.associations": { "*.qmd": "markdown" }` makes the switch permanent and disables the Quarto
  extension's editor features for `.qmd` files.

The Quarto extension's rendered-HTML preview is a separate pipeline. This extension does not style it.

## Mermaid diagrams

Diagrams are rendered by VS Code's built-in `mermaid-markdown-features` extension. Light or dark is
chosen from VS Code's colour theme, and the default Mermaid theme resolves its colours from VS Code
CSS variables, not from this extension's theme. A theme with the opposite polarity to VS Code
therefore gets diagrams in VS Code's polarity. Syncing diagram colours is not implemented.

## Development

Requirements: Node 22 and npm. Run `npm install` once.

```sh
npm run themes      # regenerate themes/themes.json and the enum lists in package.json
npm run site        # regenerate docs/site/index.html and dist/themes.html
npm run bundle      # esbuild src/extension.ts -> dist/extension.js, copy themes.json
npm run build       # themes + site + bundle
npm run typecheck   # tsc --noEmit
npm run lint        # eslint over src/, scripts/, test/, media/
npm test            # smoke test of the CSS generator across every theme
npm run check       # typecheck + lint + test; CI runs this
npm run watch       # rebuild on change; F5 in VS Code launches an Extension Development Host
npm run package     # check, then vsce package (vscode:prepublish runs build)
node scripts/harness.mjs /tmp/mpt-harness dracula   # static pages emulating the preview and the editor, for browser checks
```

Layout:

```
src/                   extension source (TypeScript, bundled by esbuild)
  extension.ts         activation, markdown-it hook, commands, URI handler, CSS file watcher, browser webview
  editor-panel.ts      theme editor webview host
  config.ts            settings read and write
  theme-css.ts         palette + settings -> stylesheet (no vscode import)
media/                 static assets shipped in the .vsix
  editor.{js,css}      theme editor UI
  preview-base.css     VS Code's preview layout rules, scoped for the editor pane
  sample.md            sample document
  icon.png             extension icon
themes/themes.json     extracted palettes (generated, committed; the data contract for src/theme-css.ts)
scripts/               build tooling (Node, ESM)
  extract-themes.mjs   CodeMirror CSS -> themes/themes.json, package.json enums
  site.mjs             theme browser page -> docs/site/index.html, dist/themes.html
  bundle.mjs           esbuild
  harness.mjs          static emulation pages for visual checks
  lib.mjs              shared helpers: root path, in-memory bundle of theme-css.ts, themes.json and sample.md readers, markdown-it
test/smoke.mjs         generator checks
vendor/                CodeMirror 5.65.21 theme stylesheets and programmingfonts' catppuccin CSS (MIT); see vendor/README.md
docs/site/index.html   theme browser page (generated, committed)
docs/screenshots/      verification screenshots
dist/                  build output (ignored by git): extension.js, themes.json, themes.html
.github/workflows/     CI: npm run check, build, generated-file drift check, vsce package
```

Generated files that are committed (`themes/themes.json`, the enums in `package.json`,
`docs/site/index.html`) are regenerated by `npm run build`. CI fails when a commit leaves them stale.
